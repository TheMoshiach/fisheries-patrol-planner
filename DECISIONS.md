# Decisions

Choices made while building, each with its reason.

| # | Decision | Reason |
|---|---|---|
| 1 | Git identity set for this repo only: GitHub login with GitHub's noreply address. | No git identity was configured on the machine; the noreply address attributes commits to the account without exposing an email. |
| 2 | Python 3.11+, with pandas, numpy, pyarrow, requests, python-dotenv, pypdf, streamlit, pytest. | All widely used and maintained PyPI packages. No skills, plugins or MCP servers were added, so no scan was needed. |
| 3 | Vessel data from the Global Fishing Watch API v3. | It provides AIS gaps, encounters, fishing effort, protected-area tags and identity. Terms checked: CC BY-NC 4.0, non-commercial, attribution required, 50,000 requests/day. The client caches every response and paces requests. |
| 4 | Ground truth is the Global Fishing Watch IUU-list indicator (official RFMO lists via the Combined IUU Vessel List). | It is the only public, official, per-vessel outcome that can be joined to AIS identities. Applied uniformly to every vessel. |
| 5 | The Combined IUU Vessel List spreadsheet is not downloaded directly. | The download asks for contact details and a reason, and its terms forbid repackaging. |
| 6 | Official RFMO list documents (IOTC, CCSBT, CCAMLR) are read only for IMO numbers, validated by check digit. | They are search seeds for finding listed vessels; they never set a label. |
| 7 | A vessel found via an IUU list is kept only if the indicator confirms a listing, and the comparison vessels drawn for it are dropped with it. | An IMO match may be a coincidence: neither a reliable positive nor a fair negative. |
| 8 | Protected-area data comes only through Global Fishing Watch; only areas the project uses are stored. | The World Database on Protected Areas restricts redistribution. |
| 9 | "Near a protected area" = apparent fishing hours within 12 nm of a watched area, from buffered activity reports. | Uses a documented API capability instead of copying boundary geometry. |
| 10 | Only AIS gaps of 12 h or more starting 50 nm or more offshore count as going dark. | Global Fishing Watch's published reliability thresholds; shorter or nearshore gaps are usually reception artefacts. |
| 11 | Gaps and encounters are fetched in full; fishing events only when flagged, plus the latest one per patrol-area vessel. | Full fishing histories are millions of events; counts come from the per-vessel indicators instead. |
| 12 | Loitering and port visits are not used. | Loitering is ambiguous for fishing vessels; port visits are not one of the requested signals. |
| 13 | Additive score with weights set a priori, not fitted to labels. | Fully explainable, and accuracy is not inflated by tuning on a small label set. |
| 14 | Evaluation metrics treat tied scores as a random draw; ranges come from resampling whole match groups. | Many vessels tie at zero and ties must not flatter the model; resampling groups respects the matched design. |
| 15 | Each listed hull is evaluated once, under the AIS identity with the longest stretch of usable history (the most recent on a tie). | One hull can appear under several names and MMSIs; counting each would count the same ship several times. |
| 16 | Comparison vessels are drawn from random days of worldwide events inside each listed vessel's own window, 30 per listed vessel, at most a few per day. | Matching on period removes year-to-year differences in AIS coverage and fleet behaviour. Drawing from events favours active vessels, which is stated as a limit. |
| 17 | Default patrol area: Galapagos and surrounding high seas; configurable. | Well-documented pressure from distant-water fleets next to major protected areas. |
| 18 | Patrol boats are an example fleet in the settings file, labelled as such. | No public source of real patrol assets exists. |
| 19 | Tables are Parquet files per stage; raw data is JSON lines; decisions are an append-only CSV. | One dataset per table with stable ids maps directly onto a hosted data platform; an append-only log is a full audit trail. |
| 20 | Raw API responses and the decision log are not committed; the cleaned real tables, features, scores and evaluation are. | Raw data is a cache and decisions are operational records. The cleaned snapshot is about 2 MB, lets the app show real data straight after cloning, and the licence (CC BY-NC 4.0) allows sharing with attribution. |
| 21 | Sample data is generated on demand, every id and name marked as sample, and never committed. | Lets the pipeline and tests run without a token while being impossible to mistake for real data. |
| 22 | Streamlit for the app, with Leaflet maps (folium and streamlit-folium); the package has no UI imports (enforced by a test). | Python-only, one command to run, and the logic stays portable. Both map packages are open source and actively released on PyPI. |
| 23 | "Last known position" is the position of the vessel's most recent recorded event. | The API does not provide live positions; the app says so. |
| 24 | Assignment suggestions are greedy: highest risk first, nearest free boat within half its range. | Easy for an officer to follow and override; a suggestion does nothing until accepted. |
| 25 | Analysis window: 12 months ending 2026-10-01. | A full year covers seasonal fleets and stays within the report API's range. |
| 26 | Explanations are template text, with no language model. | Deterministic and free to run; a language-model version belongs in the hosted platform later. |
| 27 | Flag changes are derived from vessel identity records (distinct flags in force during the window), not from the API's flag-change indicator. | That indicator is not open to public API tokens (HTTP 403). |
| 28 | Per-vessel indicators are requested one vessel at a time. | When several vessels are sent together the API returns their numbers added up, not per vessel. |
| 29 | AIS gaps longer than 30 days, or judged unintentional by the source, are not counted as going dark. | The live data contains "gaps" lasting months or years, which are lay-ups or a vessel returning under a new AIS identity, not concealment at sea. |
| 30 | Watched protected areas are named exactly as they appear in the source list ("Galapagos - Reserva Marina", "Hermandad - Reserva Marina"). | The list uses Spanish designations, so the English name matched nothing; exact names also avoid picking up the World Heritage Site and biosphere reserve that overlap the same waters. |
| 31 | The API's HTTP 201 response is treated as success. | The live API answers POST requests with 201, although the documentation examples imply 200. |
| 32 | Accuracy is measured with a year-matched look-back: each listed vessel is scored over its own last 12 months on AIS, against vessels from the same months. | In the current window none of the patrol-area vessels is listed and only one listed vessel was transmitting at all, because listed vessels mostly stop broadcasting. A current-window evaluation would measure nothing. |
| 33 | History starts on 2020-01-01 and a listed hull needs at least 500 AIS positions. | The source's per-vessel indicators reject earlier dates, and below roughly 500 positions a year the source itself declines to classify a vessel. |
| 34 | "Listed" means the indicator reports the vessel as ever IUU-listed, not listed on a particular date. | The indicator gives listing dates for only about half the vessels; requiring dates would halve an already small set. Whether the window fell before, during or after listing is recorded where known. |
| 35 | Results are reported separately for fishing vessels and support vessels, with fishing vessels as the headline. | The score is built for fishing vessels. For support vessels the only available comparison group is drawn from encounter events, which selects on one of the score's own signals, so that comparison is biased and is labelled as such rather than hidden or pooled. |
| 36 | The weights were not changed after seeing the results. | Only five listed fishing vessels exist to test against; tuning to them would overfit and make the reported accuracy meaningless. |
| 37 | A buffered protected-area report is treated as the ring around the area, and added to the hours inside. | Checked against live data: buffered reports returned fewer vessels and fewer hours than the area itself, so they cannot include it. |
| 38 | The matched AUC is the headline metric; precision in the top k is shown but not presented as a hit rate. | In a case-control sample the share of listed vessels is fixed by the design (1 in 31), so precision does not carry over to real patrols. |
| 39 | The map uses Leaflet with OpenStreetMap tiles and is the main screen. | The first map needed 3D graphics support in the browser and a Carto background that now requires an API key; it rendered blank. Leaflet needs neither, and enforcement tools in this field (Skylight, the Global Fishing Watch map) are map-first. |
| 40 | A vessel's "trail" is the sequence of places it apparently fished over the last 90 days, drawn as a dashed line and labelled as not being its track. | Vessel tracks are closed to public API tokens (HTTP 403). Fishing locations are the closest honest substitute. |
| 41 | Reserve outlines are downloaded from Global Fishing Watch, thinned to about 1 km detail, and kept on the local machine only. | They come from the World Database on Protected Areas, which restricts redistribution, so they are not committed. A fresh clone shows them after its first refresh. |
| 42 | A patrol is one boat and an ordered list of vessels, stored as one log row per vessel sharing a patrol id. Routes go nearest-vessel-first in straight lines and return to port. | Matches how a patrol is actually tasked, keeps the log append-only, and is easy for an officer to check by eye. Weather, currents and land are not modelled, and the app says so. |
| 43 | "Refresh data" runs the same download as the command line in a separate background process that reports through a status file and a log. Only one runs at a time. | The download takes 10 to 20 minutes; the app has to stay usable meanwhile and survive a page reload. |
| 44 | The analysis window ends "today minus 5 days" at the moment of a refresh, and everything afterwards reads the window from the dataset itself. | The source publishes with a delay of a few days. Pinning the window to the data stops the app and the data disagreeing on later days. |
| 45 | Settings changed in the app are saved to `config/overrides.json` and laid over `config/settings.toml`; they are validated before being written. | Keeps the documented defaults intact, needs no extra library, and a bad value cannot break the app. Boat and weight changes rebuild the ranking at once; a new patrol area needs a refresh because it needs different data. |
| 46 | The app no longer falls back to synthetic sample data. With no data it shows a refresh button. Generated data is still labelled if it is ever loaded. | Real data is available, and a silent fallback to made-up vessels is a hazard in an enforcement tool. The generator remains for tests. |
| 47 | A watchlist or dismissal stays in force after a data refresh. | An officer who has ruled a vessel out (for example a licensed local boat) should not have to do it again every refresh. The log keeps the score seen at the time. |
| 48 | Each evaluation group draws its comparison vessels from its own random stream. | With one shared stream, a change in one group reshuffled every later group, and the accuracy figures moved between refreshes for no real reason. |
| 49 | A specific "dataset deprecated" 422 response from the events service is retried, and a failed sampling day is skipped. | It appeared mid-run on requests that succeed moments later; one such fault should not waste a 15-minute refresh. |
| 50 | The app's reliability page shows only the fishing-vessel result in plain words; the support-vessel and pooled figures live in the README. | An officer needs to know how far to trust the ranking, not read a statistics table. Nothing is hidden: the full tables remain in the README and the `report` command. |
| 51 | A desktop shortcut is created by `tools/create_shortcut.ps1`. | So the app starts with a double-click and no terminal. |
